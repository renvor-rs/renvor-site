## The one-sentence version

**The code in this repository is open source; the Renvor name and marks are not.** You may
say true things about Renvor and link to it freely. You may not use the Renvor name or marks
in a way that suggests your project is Renvor, is official, or is endorsed by it.

## Why these are separate

Renvor's source code and documentation are licensed under
[`MIT OR Apache-2.0`](#licence-for-code-in-this-repository). Those licences grant rights to
**copyrighted work** — the code, the text, the structure. They deliberately do **not** grant
rights to **trademarks and brand identity**, and the Apache-2.0 licence says so explicitly in
its section 6.

That is not an oversight in the licences and it is not a restriction added here. It is how
open-source licensing has always worked: the code is free so anyone can build on it, and the
name is controlled so users can tell what is genuinely Renvor. **A permissive licence on the
code does not make the name a free-for-all**, and no statement in this project should be read
as implying otherwise.

Rust, Python, Linux, and most established open-source projects separate these two things the
same way, for the same reason.

## What this policy covers

The **Renvor brand assets**:

- the name **Renvor**, and the executable name **`renover`**
- the Renvor mark and logo in every form, including `static/img/renvor-mark-v7.svg`,
  `renvor-mark-v7-dark.svg`, and `renvor-favicon-v7.svg`
- wordmarks, illustrations, icon sets, colour-and-type combinations, and other visual
  identity produced for Renvor
- the overall visual identity of the Renvor website

**All rights in these are reserved.** No licence to them is granted by this repository, by
the framework repository, or by any Renvor documentation.

## You may do these without asking

These uses are welcome and need no permission:

| | |
|---|---|
| **Say true things about Renvor** | "Built with Renvor", "compatible with Renvor", "a Renvor plugin", "we migrated from X to Renvor" — nominative use, describing an actual relationship that exists |
| **Link to the project** | Any link to the official repository, site, or documentation, using the name as the link text |
| **Use the mark to link to us** | An unmodified Renvor mark as a link back to the official project |
| **Screenshots** | Screenshots of Renvor, its site, its output, or its documentation — in articles, talks, courses, reviews, books, and comparisons |
| **Write about Renvor** | Tutorials, blog posts, videos, critiques, benchmarks, and comparisons, favourable or not |
| **Community discussion** | Naming Renvor in forums, chats, issues, conference talks, and user-group titles |
| **Academic and journalistic use** | Citation, quotation, and reporting |

**Criticism does not require permission and will not be refused.** A brand policy that could
be used to suppress an unfavourable review would be a bad policy.

## The test to apply

When this policy does not obviously answer your question, ask:

> **Could a reasonable person, seeing this, conclude that my project is Renvor, is an official
> part of Renvor, or is endorsed by Renvor?**

If yes, ask first. If no, you are almost certainly fine.

## Forks

**You may fork the code.** The licence grants that, and nothing here restricts it.

**Give your fork its own name.** A fork may state truthfully that it is "a fork of Renvor" or
"based on Renvor" — that is nominative use and it is permitted. It may not be *called* Renvor,
carry the Renvor marks as its own identity, or present itself as the official project.

presence in a repository carrying a permissive code licence does not place them under it.

## The archived branding directories are not covered

Renvor's historical branding explorations are kept in a **local archive outside every
repository** and are **not published, not licensed, and not covered by this policy**. Nothing
in this document grants any right to them, and this policy makes no statement about their
status.

## Changes

This policy may change. Changes apply going forward and are not retroactive: a use that was
permitted when you made it does not become a violation because the policy was later revised.
